# 生成链路：cyberspace → AutoDL → 算力机 ComfyUI（MiniMax H3）

产品不直连 GPU，也不直打 ComfyUI `:8188`。生图 / 生视频从 cyberspace 画布进入 AutoDL 编排，编排经 SSH 隧道调用租赁实例上的 ComfyUI。登录口令与动态端口只写在 [服务器&ssh.md](./服务器&ssh.md)。总图见 [算力系统设计.md](./算力系统设计.md)。

## 1. 调用链

```text
cyberspace 画布
  POST /api/ai/generate-image
  POST /api/ai/generate-video
        │  本地算力服务商（extra.localCompute，地址 :8090）
        ▼
AutoDL 编排  POST /v1/jobs
        │  SSH 隧道  127.0.0.1:8188 → 实例内 ComfyUI
        ▼
租赁实例  /root/autodl-tmp/ComfyUI
        │  /upload/image  →  /prompt  →  /history  →  /view
        ▼
MiniMax H3 节点 + models/ 权重
        │
        ▼
产物  GET /v1/jobs/{id}/file
```

画布上的本地服务要保存成走编排 `:8090`。若服务商仍指向 `:8188`，请求会绕开 AutoDL，打到本机另一套 ComfyUI。

文本走另一条通道：`llm.chat` → 隧道 `:8088` llama。5090 32GB 上 H3 与 llama 不能同时驻留。

## 2. 画布模式和 H3 节点

H3 是视频模型，没有文生图 / 图生图节点。cyberspace 的播放模式对应关系如下。

| 画布 | 工作流 id | ComfyUI 节点 | 权重 | 状态 |
|------|-----------|--------------|------|------|
| 文生图 | `t2i.demo` | 无 | 本卡无文生图权重 | 编排返回 Mock 图，不进 ComfyUI |
| 图生图 | — | 无 | 无 | `422`，改走云端 |
| 文生视频 `text` | `t2v.u03` | `MiniMaxH3ImageToVideo` 不接图 | `minimax_h3_fl2va_…int8` | 工作流在 `platform/workflows/minimax_h3_txt2vid.json` |
| 首帧 `first_frame` | `t2v.i2v` | 同上，接 `first_frame` | 同上 fl2va | 工作流在 `platform/workflows/minimax_h3_img2vid.json` |
| 首尾帧 `first_last_frame` | `t2v.flf2v` | 同上，再接 `last_frame` | 同上 fl2va | 工作流在 `platform/workflows/minimax_h3_flf2vid.json`；`image_ref` 为首帧，`end_image_ref` 为尾帧 |
| 多图 `multi` | `t2v.r2v` | `MiniMaxH3ReferenceToVideo` | `minimax_h3_ref2va_…int8` | `image_refs` 2–9 张；提示词用 `<Picture 1>`。工作流 `platform/workflows/minimax_h3_ref2vid.json` |
| 全能参考 `omni` | 未接 | 同上，还可接参考视频和音频 | ref2va | 含视频/音频仍 `422`，只传图用 `multi` |

`POST /v1/jobs` 已接收：`play_mode`、`width`、`height`、`duration`、`fps`、`seed`、`image_ref`、`end_image_ref`、`image_refs`。图用 data URL、http(s) 或 base64。CLI 见 `guide/CLI接口.md`。

H3 约束（编排里已按这个收口）：

- 16:9 用 **1344×768**。边长对齐 32，长边不超过 1344。
- 帧数对齐 **17k+5**。当前任务最长 **124 帧**（约 5 秒 / 24fps）。
- 首尾帧缺任意一张图、多图不足 2 张或超过 9 张时 `422`。带视频/音频的全能参考仍 `422`。

盘上还有：`qwen3vl_32b_minimax_h3_…` 文本编码器、video/audio VAE、fl2v 与 ref2v 的 turbo LoRA。

## 3. 工作流从本机到算力机

画布稿和编排用的 API 图分开。

| 步骤 | 位置 | 格式 |
|------|------|------|
| 1. 画布稿 | ComfyUI 仓 `comfyui工作流仓库/<模型>/` | 画布 JSON（`nodes` / `links`）。H3 放 `minimax-h3/` |
| 2. 并入同步缓冲 | `scripts/import-workflow-repo.sh` → `Source/user-workflows/` | 同上，按子目录原样拷入 |
| 3. 推到实例侧边栏 | `./scripts/sync-mirror.sh autodl` 或 `./scripts/sync-source.sh` | 远端 `/root/autodl-tmp/ComfyUI/user/default/workflows/` |
| 4. 编排真正提交的图 | AutoDL `platform/workflows/*.json` | API 图：`prompt` + `inject`。adapter 打 `/prompt` |

技能包仍走 `Source/workflows/`（manifest），与侧边栏 JSON 不是同一目录。同步不含 `models/`。

```bash
# ComfyUI 仓
./scripts/import-workflow-repo.sh          # 仓库 → Source/user-workflows
./scripts/sync-mirror.sh autodl            # Source ↔ 实例（含侧边栏）
```

侧边栏里看见工作流，只说明 JSON 到了实例。AutoDL 要能提交，还得有一份对应的 `platform/workflows/` API 图，并在 `services.json` 里有 id。

## 4. 跑起来还要满足的条件

工作流同步解决不了进程和显卡。当前实例（见 [服务器&ssh.md](./服务器&ssh.md)）核对结果：

| 项 | 要求 | 现状 |
|----|------|------|
| GPU | 容器内可见 `/dev/nvidia*` | 未挂上。`nvidia-smi` 是空文件 |
| ComfyUI | 实例内 `0.0.0.0:8188` | 进程未起 |
| 隧道 | 本机 `127.0.0.1:8188` 转到实例 | 未接。本机 8188 是另一套没有 H3 节点的 ComfyUI |
| 编排 | `:8090` `POST /v1/jobs` | 已在跑。视频任务会打到本机那套 ComfyUI 并因缺节点失败 |

顺序：控制台挂上 GPU → 实例内启动 ComfyUI → 停掉占用本机 8188 的进程 → 开隧道 → 再提交视频任务。

## 5. 补首尾帧和全能参考时改哪里

1. 在 `comfyui工作流仓库/minimax-h3/` 画好工作流（首尾帧接 `first_frame` + `last_frame`；全能参考用 `MiniMaxH3ReferenceToVideo`）。
2. `import-workflow-repo.sh` 后 `sync-mirror.sh autodl`，侧边栏能打开。
3. 导出 API 图到 AutoDL `platform/workflows/`，写好 `inject`（提示词、宽高、帧数、种子、图片文件名）。
4. 编排上传对应素材：首尾帧两张图；全能参考最多 9 图、3 视频、3 音频。只同步 JSON、不改上传，采样器拿不到输入。
5. 首尾帧已落到 `t2v.flf2v`。全能参考的 `play_mode` 仍是 `422`。
