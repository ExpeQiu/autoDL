# 并发任务队列完整教程（P07 动作迁移示例）

本文介绍如何在管理面板中完成一次完整的并发生成任务：

1. 配置 AutoDL Token；
2. 批量创建多台镜像机；
3. 等待镜像机和 ComfyUI 就绪；
4. 上传任务所需的图像、视频素材；
5. 使用 `P07-动作迁移-Wan2.2AnimateV4.json` 创建任务；
6. 批量设置每个任务的输入素材和参数；
7. 智能分配任务并开始执行；
8. 查看生成结果；
9. 将结果打包并下载到本地；
10. 任务结束后关闭或释放镜像机。

> P07 是动作迁移视频工作流。每个任务至少需要一张角色图像和一个参考动作视频。示例假设需要生成 4 个视频，因此准备 4 张图像和 4 个参考视频（可以是同一个视频），并创建 4 个排队任务。

---

## 一、开始前准备

### 1. 准备 AutoDL Token令牌

1. 登录 AutoDL https://www.autodl.com/console/center/settings/token
2. 打开 AutoDL 控制台的 Token令牌 设置页面。
3. 创建或复制可用 Token令牌。
4. 不要将 Token令牌 发给其他人，也不要截图公开。

管理面板中的 Token令牌 只保存在当前浏览器本地缓存，不会写入服务器配置文件。

### 2. 准备 P07 输入素材

每个 P07 任务需要：

- 一张角色或人物图像；
- 一个参考动作视频。

本教程以 4 个任务为例：

```text
图像：
person-01.png
person-02.png
person-03.png
person-04.png

视频：
motion-01.mp4
motion-02.mp4
motion-03.mp4
motion-04.mp4
```

建议：

- 图像主体清晰、人物无遮挡，最好为纯正面人物再画面中心；
- 参考视频中的人体动作完整可见；
- 输入视频不要超过本次需要处理的时长；
- 文件名尽量有规律，便于确认图像和视频的对应顺序；
- 先在本地整理好排序，例如 `01、02、03、04`。

## 二、创建多台镜像机器

### 1. 进入机器管理

1. 在左侧导航打开 **并发生成**。
2. 点击顶部 **机器管理**。
3. 在 **AutoDL Token** 输入框中粘贴 Token。
4. 等待主机列表刷新。

页面中的 **主机集群** 会显示：

- 当前主机总数；
- 已就绪主机数量；
- 镜像机数量；
- 本机主控；
- 每台机器的电源、GPU、ComfyUI 和任务状态。

### 2. 打开创建实例窗口

1. 在 **主机集群** 区域点击右侧 **创建实例**。
2. 弹出 **创建镜像实例** 窗口。

窗口内需要设置：

- **GPU 规格**：选择适合 P07 工作流的 GPU；
- **系统盘扩容 (GB)**：没有额外需要时可保持 `0`；
- **创建数量**：支持一次创建 1～10 台；
- **应用 UUID**：默认值为 `BmAgGF99mx`；
- **优先区域**：可选择西北区、北京区，也可以不选，让平台按可用资源创建。

> 创建的实例按 AutoDL 应用市场正常计费。创建多台就会按多台机器计费，面板不会改变官方价格。

### 3. 示例：创建 4 台镜像机

1. **创建数量** 调整为 `4 台`。
2. 确认 Token 和应用 UUID 已填写。
3. 点击 **创建镜像实例**。
4. 页面显示“正在依次提交 4 台创建请求”。
5. 提交成功后进入等待阶段，首次通常需要 1～3 分钟。
6. 出现“4 台实例已全部就绪，已添加到主机列表”后点击 **关闭**。

镜像机会按短编号命名，例如：

```text
并发镜像机01
并发镜像机02
并发镜像机03
并发镜像机04
```

### 4. 确认 ComfyUI 就绪

返回 **主机集群 → 镜像机** 列表，逐台确认：

- 电源状态为 **运行中**；
- ComfyUI 状态为 **就绪**。

如果机器运行中但 ComfyUI 显示 **未启动**：

- 单台点击 **启动Comfy**；
- 多台可点击右上角 **全部启动Comfy**。

只有电源运行且 ComfyUI 就绪的主机才能接收任务。

> 如果 P07 所需模型、自定义节点或工作流依赖在镜像中不完整，实例虽然可能显示就绪，但执行时仍会失败。应确保创建实例时使用的是包含 P07 完整环境的应用镜像。

## 三、上传并管理输入素材

### 1. 进入素材管理

1. 在 **并发生成** 页面点击顶部 **素材管理**。
2. 页面显示上传区域和素材列表。

上传后的文件按类型保存在：

```text
图像：/root/并发/image
视频：/root/并发/video
音频：/root/并发/audio
```

### 2. 上传图像

1. 点击素材类型 **图像**。
2. 点击上传框，或将 4 张图像拖入上传框。
3. 等待显示“上传中 (已完成数/总数)”。
4. 上传完成后确认列表中出现 4 张图像。

### 3. 上传视频

1. 点击素材类型 **视频**。
2. 点击上传框，或将 4 个参考视频拖入上传框。
3. 等待全部上传完成。
4. 确认列表中出现 4 个视频。

素材列表会显示：

- 缩略图；
- 文件类型；
- 文件名；
- 本地路径；
- 图像或视频尺寸；
- 文件大小。

点击本地路径可复制单个路径。勾选多个文件后可以使用 **复制路径**。

> 不建议把图像和视频混在同一次“带入批量参数”操作中。P07 有两个文件参数，图像和视频应分别写入对应参数。

---

## 四、选择 P07 API 并创建任务队列

### 1. 进入批量生成

1. 点击顶部 **批量生成**。
2. 在 **任务队列** 右侧 API 下拉框中选择：

```text
P07-动作迁移-Wan2.2AnimateV4.json
```

切换 API 会重新加载参数，并清空之前属于其他 API 的任务队列。

### 2. 添加任务

本例有 4 组素材：

1. 在 **数量** 中输入 `4`。
2. 点击 **添加任务**。
3. 任务队列统计应显示：

```text
4 总计
4 等待
```

每个任务都可以展开，查看或单独修改参数。批量任务建议先通过 **批量设置参数** 完成统一配置。

---

## 五、使用 P07 批量设置参数

点击任务队列右侧 **批量设置参数**。

弹窗左侧为 API 参数列表，右侧为当前参数的批量输入区。每一项与排队任务按顺序一一对应：

```text
第 1 项 → 第 1 个排队任务
第 2 项 → 第 2 个排队任务
第 3 项 → 第 3 个排队任务
第 4 项 → 第 4 个排队任务
```

P07 当前开放 5 个参数：

| 节点 | 页面参数 | 用途 | 示例值 |
|---|---|---|---|
| `#57` | `LoadImage / image` | 角色输入图像 | `/root/并发/image/person-01.png` |
| `#997` | `VHS_LoadVideo / video` | 参考动作视频 | `/root/并发/video/motion-01.mp4` |
| `#1001` | `INTConstant / value` | 输出宽度 | `468` |
| `#1002` | `INTConstant / value` | 输出高度 | `832` |
| `#1003` | `INTConstant / value` | 最大加载帧数 | `900` |

左侧可能出现多个同名的 `INTConstant / value`，请根据参数前的节点编号 `#1001、#1002、#1003` 区分。

### 1. 批量设置角色图像

1. 左侧点击节点 **#57 `LoadImage / image`**。
2. 点击 **从素材库选择路径**。
3. 只选择本次任务使用的 4 张图像。
4. 按任务顺序选择：`person-01` 到 `person-04`。
5. 点击 **写入参数**。
6. 下方应显示 4 行图像路径。
7. 检查“已输入 `4 / 4` 项”。

示例：

```text
/root/并发/image/image_xxx_01.png
/root/并发/image/image_xxx_02.png
/root/并发/image/image_xxx_03.png
/root/并发/image/image_xxx_04.png
```

### 2. 批量设置参考视频

1. 左侧点击节点 **#997 `VHS_LoadVideo / video`**。
2. 点击 **从素材库选择路径**。
3. 只选择 4 个参考视频。
4. 按任务顺序选择：`motion-01` 到 `motion-04`。
5. 点击 **写入参数**。
6. 检查“已输入 `4 / 4` 项”。

示例：

```text
/root/并发/video/video_xxx_01.mp4
/root/并发/video/video_xxx_02.mp4
/root/并发/video/video_xxx_03.mp4
/root/并发/video/video_xxx_04.mp4
```

### 3. 设置输出宽度

1. 左侧选择节点 **#1001 `INTConstant / value`**。
2. 第一行填写 `468`。
3. 点击 **首项填充全部**。
4. 确认出现 4 行 `468`。

### 4. 设置输出高度

1. 左侧选择节点 **#1002 `INTConstant / value`**。
2. 第一行填写 `832`。
3. 点击 **首项填充全部**。
4. 确认出现 4 行 `832`。

### 5. 设置最大加载帧数

1. 左侧选择节点 **#1003 `INTConstant / value`**。
2. 第一行填写所需帧数。
3. 点击 **首项填充全部**。

P07 输入帧率按 30 FPS 计算：

| 目标上限 | 帧数 |
|---|---:|
| 10 秒 | `300` |
| 20 秒 | `600` |
| 30 秒 | `900` |

默认值为 `900`，即最多按约 30 秒加载参考视频。

> 更长的视频、更多帧和更高分辨率会增加生成时间、显存占用和失败概率。初次测试建议先用 10 秒，即 `300` 帧。

### 6. 应用参数

确认所有已修改参数都没有红色错误提示，并且每个参数均为 `4 / 4` 项，然后点击：

```text
应用到 4 个任务
```

弹窗关闭后，点击任一任务行展开参数，可以检查：

- 图像路径前是否显示正确缩略图；
- 视频路径是否与该任务匹配；
- 宽度、高度、帧数是否正确。

如果需要再次批量修改，重新打开 **批量设置参数**。已应用的队列数据会自动回填。

### 7. 关于文本参数的两种导入模式

其他 API 如果开放文本或提示词参数，会显示：

- **逐行导入**：一行对应一个任务；
- **多行分段**：一条提示词可以包含多行。

多行分段时，在两条任务文本之间单独放置：

```text
--- ZEALMAN TASK ---
```

切换导入模式只改变解析方式，不会修改原文本或自动增删分隔符。

## 六、将任务分配给多台镜像机

返回任务队列后点击 **智能分配**。

系统会把等待任务分配到已就绪的镜像机。4 台镜像机和 4 个任务通常会形成一台一任务的分配。

逐项检查任务行中的主机下拉框，确认：

- 每个任务已经分配到目标镜像机；
- 对应主机显示 **ComfyUI 已就绪**；
- 没有出现“没有可执行任务的就绪主机”提示。

如需手工调整，可以在任务行的主机下拉框中指定镜像机。

> **智能分配**主要面向已就绪镜像机。如果没有镜像机就绪，该按钮不可用。

---

## 七、设置超时并开始执行

### 1. 阅读并发须知

在 **批量生成** 顶部右侧点击 **并发须知**，重点确认：

- 视频任务应设置足够长的结果等待时间；
- 高分辨率和长视频会明显增加显存占用；
- 镜像机必须具备工作流依赖、模型和自定义节点；
- 大文件同步到镜像机需要额外时间；
- ComfyUI 崩溃后需要重新启动对应机器的 ComfyUI。

### 2. 设置结果等待超时

P07 属于耗时视频工作流，建议将顶部 **超时** 设置为：

```text
30 分钟或 60 分钟
```

此超时是单任务等待结果的最长轮询时间。超时后任务会标记为“轮询超时”，不代表云主机一定已经停止计算。

### 3. 是否启动前清显存

可勾选 **启动前清显存**。

适合：

- 镜像机之前运行过其他任务；
- 担心残留模型占用显存；
- 首次批量执行前希望清理运行环境。

### 4. 开始执行

确认以下条件：

- 已选择 P07 API；
- 队列中有等待任务；
- 所有任务参数正确；
- 任务已经分配到就绪主机；
- 镜像机 ComfyUI 均为就绪状态。

点击顶部右侧 **开始执行**。

执行期间任务状态可能依次显示：

```text
待执行 / 排队中
上传素材
准备中
执行中 / 生成中
已完成
执行失败
```

任务行会显示：

- 当前主机；
- 阶段；
- 进度条；
- 百分比；
- 已执行节点；
- 耗时；
- 错误信息；
- 结果缩略图。

需要中止时点击顶部 **停止**。

> 停止操作后应等待状态同步。不要立即关机，否则正在回传的结果文件可能无法下载到主控。

---

## 八、查看生成结果

任务完成后，页面下方出现 **生成结果**：

- 显示已完成任务数量；
- 显示结果文件总数；
- 标记结果来源机器；
- 视频可以直接播放；
- 页面最多展示最近 10 个结果。

点击 **在资产中查看**，页面会跳转到：

```text
我的资产 → 集群资产
```

集群资产中可以：

- 按时间线查看；
- 点击 **按机器分组**，确认每台镜像机产生的结果；
- 预览视频；
- 单个下载；
- 点击 **批量选择** 后选择多个结果；
- 点击 **下载 (数量)** 下载所选文件。

> 集群资产中的“批量下载”会依次下载多个原始文件，不会合并成一个 ZIP。如果浏览器拦截多个下载，请允许当前站点下载多个文件。

## 九、将生成结果打包为 ZIP 并下载

如果需要一个 ZIP 压缩包，使用 **资产打包**。

### 1. 进入资产打包

1. 从左侧导航进入 **我的资产**。
2. 点击顶部 **资产打包**。
3. 等待页面读取可打包资产范围。

### 2. 选择打包范围

两种方式：

- **今日**：打包今天产生的资产；
- **自定义范围**：设置开始日期和结束日期。

页面会显示：

```text
当前条件共命中 N 个资产
```

确认数量合理后再开始打包。

> 日期打包会包含该日期范围内符合条件的全部资产，不只包含当前这 4 个 P07 结果。如果当天还有其他生成结果，也会一并进入压缩包。

### 3. 开始打包

1. 点击 **开始打包**。
2. 页面依次显示“正在整理资产”或“正在打包资产”。
3. 打包完成后，ZIP 会出现在下方 **已打包资产** 列表。

列表会显示：

- ZIP 文件名；
- 日期范围；
- 文件数量；
- ZIP 大小；
- 完成时间。

### 4. 下载到本地

在目标 ZIP 右侧点击 **下载**。

浏览器会把 ZIP 下载到本机默认下载目录。若浏览器询问保存位置，选择本地目录并确认。

如需下载多个历史 ZIP：

1. 勾选多个 ZIP；
2. 点击 **批量下载 (数量)**。

## 十、任务完成后的关机与释放

确认以下事项后再关闭机器：

- 所有需要的任务已完成；
- 结果已经显示在集群资产中；
- ZIP 已打包完成；
- 文件已经下载到本地并能正常打开。

然后返回：

```text
并发生成 → 机器管理
```

可选择：

- **关闭Comfy**：只停止单台镜像机的 ComfyUI，不关机；
- **全部关闭Comfy**：停止全部镜像机的 ComfyUI；
- **关机**：关闭单台实例，之后通常可以再次开机；
- **全部关机**：关闭所有镜像机，不影响本机主控；
- **释放**：永久释放实例，此操作不可撤销。

> 只要实例仍处于计费状态，就可能继续产生费用。长期不再使用时，应根据 AutoDL 计费规则及时关机或释放。

## 十一、常见问题排查

### 1. “开始执行”按钮不可点击

依次检查：

1. 是否已经选择 P07 API；
2. 是否已经添加任务；
3. 是否存在等待任务；
4. 任务是否分配给主机；
5. 目标主机是否为运行中；
6. 目标主机的 ComfyUI 是否为就绪。

### 2. 显示“没有可执行任务的就绪主机”

处理方法：

1. 返回 **机器管理**；
2. 点击 **刷新**；
3. 启动未运行的机器；
4. 点击 **启动Comfy** 或 **全部启动Comfy**；
5. 返回批量生成，重新点击 **智能分配**。

### 3. 批量参数无法应用

常见原因：

- 输入项数与等待任务数不一致；
- 4 个任务只填写了 3 行；
- 数字参数中包含非数字内容；
- 文件路径放错参数；
- 图像和视频路径混在同一个文件参数中。

弹窗底部必须显示每个已编辑参数均为：

```text
已输入 4 / 4 项
```

### 4. 图像或视频上传失败

检查：

- 文件格式是否受支持；
- 网络是否稳定；
- 文件是否过大；
- 上传过程中是否刷新了页面；
- 磁盘剩余空间是否充足。

### 5. P07 执行失败或 ComfyUI 崩溃

可能原因：

- 显存不足；
- 视频帧数过高；
- 输出分辨率过高；
- 镜像缺少模型或节点；
- 输入视频损坏；
- 素材同步超时；
- 镜像机 ComfyUI 进程崩溃。

建议：

1. 将 `#1003` 帧数从 `900` 降为 `300`；
2. 保持默认分辨率 `468 × 832`；
3. 勾选 **启动前清显存**；
4. 重启失败主机的 ComfyUI；
5. 先用 1 个任务验证，再扩大到多机并发。

### 6. 任务完成但结果页没有文件

1. 等待结果回传完成；
2. 不要在刚生成完成时立即关闭镜像机；
3. 点击 **在资产中查看**；
4. 在 **集群资产** 点击刷新；
5. 检查任务是否实际显示为完成；
6. 展开任务查看错误信息和结果链接。

### 7. ZIP 中包含其他文件

**资产打包**按日期范围收集资产，不是按当前任务队列筛选。若只需要当前 P07 结果：

- 在 **集群资产** 中使用 **批量选择**，只选择本次结果并下载原文件；或
- 在没有其他任务的独立日期范围内执行并打包。
